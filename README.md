# Автотесты интернет-магазина для GitLab и TestOps

Самостоятельный демонстрационный проект на Python, pytest и Allure. Папку можно использовать как содержимое отдельного GitLab-репозитория: она не зависит от файлов родительского проекта.

## Состав

- 70 логических автотестов с внешними ID `AUTO-SHOP-001` - `AUTO-SHOP-070`;
- 4 Feature и 8 Story, совпадающих со структурой ручных кейсов;
- 3 параметризованных теста на 6, 4 и 6 наборов;
- 83 результата в полном запуске;
- русские названия, описания и шаги;
- Feature, Story, Layer, Component, Owner, Severity и теги;
- JSON, CSV и текстовые вложения в результатах;
- управляемые Failed, Broken и Flaky сценарии;
- три длительные логические проверки для демонстрации live-загрузки результатов.

## Подготовка GitLab

1. Поместите содержимое этой папки в корень GitLab-репозитория.
2. В `Settings -> CI/CD -> Variables` добавьте защищённые переменные:

| Переменная | Назначение |
| --- | --- |
| `ALLURE_ENDPOINT` | Адрес вашей инсталляции TestOps |
| `ALLURE_PROJECT_ID` | ID проекта TestOps |
| `ALLURE_TOKEN` | Токен сервисной учётной записи |
Токены и внутренние адреса не нужно сохранять в репозитории.

## Подготовка GitHub Actions

Workflow находится в `.github/workflows/testops-online-store.yml`. В настройках
GitHub-репозитория добавьте:

| Тип | Имя | Назначение |
| --- | --- | --- |
| Repository variable | `ALLURE_ENDPOINT` | Адрес вашей инсталляции TestOps |
| Repository variable | `ALLURE_PROJECT_ID` | ID проекта TestOps |
| Repository secret | `ALLURE_TOKEN` | Токен сервисной учётной записи |

Workflow запускается вручную из раздела Actions или из TestOps. При ручном запуске
можно выбрать `Browser`, `City`, релиз, режим flaky-тестов и длительность задержки.
Параметры `ALLURE_JOB_RUN_ID` и `ALLURE_USERNAME` заполняются только при запуске из
TestOps.

## Управление демонстрацией

| Переменная | Значение | Поведение |
| --- | --- | --- |
| `SHOP_DEMO_FLAKY` | `auto` | Шесть flaky-тестов независимо падают с вероятностью 40% |
| `SHOP_DEMO_FLAKY` | `pass` | Все flaky-тесты проходят |
| `SHOP_DEMO_FLAKY` | `fail` | Все flaky-тесты падают |
| `SHOP_DEMO_DELAY_SECONDS` | `5` | Три логические проверки работают с заметной задержкой |
| `SHOP_DEMO_DELAY_SECONDS` | `0` | Быстрый технический прогон |
| `SHOP_DEMO_ENV` | `stage` | Окружение запуска |
| `SHOP_DEMO_RELEASE` | `2026.08-store-rc1` | Версия продукта, к которой относится запуск |

При `SHOP_DEMO_FLAKY=pass` ожидаются 73 Passed, 6 Failed и 4 Broken среди 83 результатов. При `fail` ожидаются 67 Passed, 12 Failed и 4 Broken.

Задержки нужны для демонстрации `allurectl watch`: завершённые результаты появляются в TestOps во время выполнения pipeline, поэтому разбор можно начать до окончания всего запуска.

## Локальный запуск

Из этой папки:

```powershell
python -m pip install -r requirements.txt
$env:SHOP_DEMO_FLAKY = "pass"
$env:SHOP_DEMO_DELAY_SECONDS = "0"
python -m pytest tests --alluredir=allure-results --clean-alluredir -p no:cacheprovider
```

Для проверки заранее известных дефектов не используются `xfail` или `skip`: TestOps получает настоящие Failed и Broken результаты, на которых можно показывать разбор запуска, дефекты, перезапуск и аналитику.

Все пользователи, адреса, товары, платежи и ссылки в проекте являются демонстрационными.
